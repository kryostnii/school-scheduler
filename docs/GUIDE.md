# Полный гайд по работе с проектом School Scheduler

## 1. Что это за проект

Десктопное приложение (PySide6 + SQLAlchemy + SQLite) для автоматического составления школьного расписания по белорусским нормам. Алгоритм: генетический алгоритм + бэктрекинг.

## 3. Установка и запуск

### 3.1. Виртуальное окружение и зависимости

```bash
# Создание venv (если ещё нет)
python3 -m venv venv

# Активация
source venv/bin/activate          # Linux/macOS
venv\Scripts\activate             # Windows

# Установка зависимостей
pip install -r requirements.txt
```

### 3.2. Запуск GUI

```bash
# Linux
./run_gui.sh

# Windows
run_gui.bat

# Или напрямую
python -m app.main
```

При первом запуске `init_db()` в `app/main.py` создаёт файл `school.sqlite3` в корне проекта по схеме `db/schema.sql`, заполняет таблицы `shifts` (I/II смена) и `academic_years` (текущий год).

### 3.3. Запуск без GUI (тест пайплайна)

```bash
python scripts/run_from_db.py            # Создаст school.sqlite3 с тестовой школой
python scripts/run_sample.py             # Запуск алгоритма без БД (только stdlib)
```

## 4. Архитектура приложения

### 4.1. Точка входа (`app/main.py`)

```
init_db()          →  создаёт/проверяет school.sqlite3
make_engine()      →  SQLAlchemy engine (sqlite:///school.sqlite3)
QApplication       →  PySide6 окно
MainWindow(engine) →  главное окно с 4 вкладками
```

### 4.2. База данных (`db/schema.sql` + `app/data/models.py`)

10 таблиц, ключевые связи:

```
academic_years ──┐
                  ├── classes ──┐
shifts ──────────┘              ├── class_subjects ── subject_groups ── timetable_entries
                                 │                    │                  │
subjects ────────────────────────┘                    │                  │
                                                      │                  ├── cabinet_id
teachers ─────────────────────────────────────────────┘                  │
                                                                        └── paired_entry_id
cabinets ───────────────────────────────────────────────────────────────────┘
```

**Атомарная единица планирования** — `subject_groups` (класс/подгруппа). Каждая запись = один урок-час в неделю для конкретной подгруппы с конкретным учителем.

- `class_subjects` = какой предмет изучается в классе, сколько часов/неделю, делится ли на подгруппы
- `subject_groups` = кто преподаёт эту подгруппу, в каком кабинете
- `timetable_entries` = итоговый слот (день + урок) для каждой подгруппы

### 4.3. Алгоритм (`app/services/reference_scheduler.py`)

Генетический алгоритм с бэктрекингом:

1. **Инициализация** — случайные расписания (хромосомы)
2. **Оценка** — подсчёт hard-конфликтов (учитель в двух местах, занятый кабинет) и soft-штрафов (окна, нарушения порядка)
3. **Селекция** — турнирная
4. **Кроссовер** — обмен участками двух хромосом
5. **Мутация** — случайная перестановка одного урока
6. **Бэктрекинг** — заполнение пустых слотов с проверкой ограничений

### 4.4. Мост БД → алгоритм (`app/services/db_context_builder.py`)

`build_context_from_db(conn, year_id)` — читает БД через `sqlite3` (без SQLAlchemy), собирает `ScheduleContext`:

- Классы, подгруппы, учителя, кабинеты
- Sanpin-правила (включённые)
- Расписание звонков
- Учительские пожелания

`save_chromosome_to_db(conn, ctx, chromosome)` — записывает результат обратно в `timetable_entries`.

## 5. Интерфейс приложения

### 5.1. Боковая навигация (MainWindow)

4 вкладки, переключение по кнопкам или Ctrl+1..4:

| Ctrl+ | Вкладка      | Назначение                                      |
|-------|--------------|------------------------------------------------|
| Ctrl+1 | Данные       | Учителя, классы, предметы, кабинеты, учебные планы |
| Ctrl+2 | Генерация    | Настройка и запуск алгоритма                    |
| Ctrl+3 | Расписание   | Просмотр, редактирование, обмен                 |
| Ctrl+4 | Настройки    | Санитарные нормы (вкл/выкл)                    |

Кнопка «Открыть БД...» (Ctrl+O) — загрузка другого файла `.sqlite3`.

### 5.2. Вкладка «Данные» (DataPage)

5 табов:

1. **Учителя** — ФИО, часов/неделю, кабинет, смена
2. **Классы** — номер (5А, 11Б), параллель, буква, смена
3. **Предметы** — название, трудность, физкультура, тяжёлый, сдвоенные
4. **Кабинеты** — номер, вместимость, тип, смена
5. **Учебные планы** — пошаговый интерфейс:
   - **Шаг 1**: выбрать предмет класса (сколько часов, деление на подгруппы)
   - **Шаг 2**: назначить учителя и кабинет для подгруппы

### 5.3. Вкладка «Генерация» (GenerationPage)

- **Пресеты**: Быстро (~1 мин), Стандарт (~3 мин), Качественно (~10 мин)
- **Параметры**: вариантов в памяти (популяция), шагов улучшения (генерации)
- **Расширенные**: мутация, кроссовер, зерно генератора
- **Прогресс**: полоса, статус, количество ошибок, лог
- Кнопка «Найти расписание» (запуск) / «Остановить»

### 5.4. Вкладка «Расписание» (TimetablePage)

- **Просмотр** по классам / учителям / кабинетам (переключатель)
- **Фильтр по смене** (все / I / II)
- **Режим редактирования**: клик по уроку → «Поменять местами» → выбор целевого слота
- **Отмена** (Ctrl+Z) — один последний обмен
- **Конфликты** — подсветка красным (учитель в двух местах, занятый кабинет)
- **Сплит-группы** — не считаются конфликтами (разные подгруппы одного предмета)

### 5.5. Вкладка «Настройки» (SettingsPage)

Включение/отключение санитарных правил (sanpin_rules):
- Физкультура не два дня подряд
- Макс. уроков по классам (1кл: 4, 2-4кл: 5, 5-6кл: 6, 7-11кл: 7)
- 1 класс — только I смена
- Тяжёлые предметы — не первым/последним уроком
- Пиковые нагрузки: вт/ср

## 6. Порядок работы (пошагово)

### Шаг 1: Заполнить данные

1. Открыть приложение → вкладка «Данные»
2. **Кабинеты** → «Добавить» (номер, тип, смена)
3. **Предметы** → «Добавить» (название, трудность, флаги)
4. **Учителя** → «Добавить» (ФИО, часов/неделю, кабинет, смена)
5. **Классы** → «Добавить» (номер, буква, смена)

### Шаг 2: Настроить учебные планы

1. Вкладка «Данные» → таб «Учебные планы»
2. **Шаг 1** — добавить предметы класса:
   - Класс: 5А
   - Предмет: Математика
   - Часов/неделю: 5
   - Split: нет
3. **Шаг 2** — добавить подгруппу:
   - Выбрать предмет класса в таблице выше
   - Учитель: Иванова А.П.
   - Кабинет: 101
4. Повторить для всех предметов и классов

### Шаг 3: Запустить генерацию

1. Вкладка «Генерация»
2. Выбрать пресет (рекомендую «Стандарт»)
3. Нажать «Найти расписание»
4. Дождаться завершения (прогресс-бар + лог)

### Шаг 4: Просмотреть результат

1. Вкладка «Расписание»
2. Выбрать класс в выпадающем списке
3. Уроки отображаются в таблице по дням недели
4. Красная подсветка — конфликт (учитель/кабинет)

### Шаг 5: Правки (опционально)

1. Включить «Режим редактирования»
2. Кликнуть на урок
3. Нажать «Поменять местами с другим классом»
4. Выбрать целевой слот в диалоге
5. Отмена — кнопка «Отменить» (или Ctrl+Z)

## 8. Алгоритм (справочно)

### 8.1. Ограничения

**Hard-конфликты** (недопустимы):
- Учитель в двух классах одновременно
- Два урока в одном кабинете одновременно
- Урок за пределами расписания звонков
- Нарушение max уроков/день для класса

**Soft-штрафы** (нежелательны):
- Окна у учеников/учителей
- Нарушение порядка предметов по трудности
- Физкультура два дня подряд
- Тяжёлый предмет первым/последним уроком

### 8.2. Параметры

| Параметр        | Быстро | Стандарт | Качественно |
|----------------|--------|----------|-------------|
| Популяция      | 40     | 80       | 200         |
| Поколения      | 150    | 400      | 1000        |
| Мутация        | 0.1    | 0.1      | 0.1         |
| Кроссовер      | 0.8    | 0.8      | 0.8         |

## 11. Известные особенности

1. **C++ ядро не скомпилировано** — используется Python reference-реализация (`reference_scheduler.py`). Исходники C++ в `core/` готовы, но требуют pybind11 + CMake.

2. **`db_context_builder.py`** использует сырой `sqlite3` (не SQLAlchemy) — это осознанно для работы без зависимостей. Переписать под SQLAlchemy — тривиально.

3. **Path на Windows** — SQLAlchemy URI требует `pathlib.Path.as_posix()` (прямые слэши), иначе `sqlite3.OperationalError`.

4. **`init_db()` в `main.py`** создаёт таблицы через `schema.sql`, но seed-данные (смены, учебный год) добавляются через raw SQL, а не через SQLAlchemy модели.

5. **Обмен уроками** — двухсторонний:源 entry переносится в целевой слот, целевой — в исходный. Отмена работает только для последнего действия.

6. **Split-группы** — не считаются конфликтами в TimetablePage (разные подгруппы одного предмета могут стоять в одно время).

## 12. FAQ

**Q: Не запускается GUI**
```bash
# Проверьте, что venv создан и зависимости установлены:
source venv/bin/activate
pip install -r requirements.txt
python -m app.main
```

**Q: Ошибка `cannot import name 'QShortcut'`**
Была ошибка в импорте — исправлено. `QShortcut` импортируется из `PySide6.QtGui`, а не `QtCore`.

**Q: Пустое расписание на вкладке «Расписание»**
Убедитесь, что учебные планы заполнены (шаг 1 и 2 в табе «Учебные планы») и генерация выполнена.

**Q: Конфликты после генерации**
Попробуйте пресет «Качественно» или увеличьте шаги улучшения. Можно исправить вручную в режиме редактирования.

**Q: Как открыть другую базу данных**
Кнопка «Открыть БД...» внизу бокового меню (или Ctrl+O).
