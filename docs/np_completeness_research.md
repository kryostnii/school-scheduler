# Исследование вычислительной сложности задачи составления школьного расписания

**Проект:** School Scheduler  
**Статус:** исследовательская записка для прототипа  
**Версия документа:** 1.0  
**Дата:** 2026-11-09

## Аннотация

Составление школьного расписания относится к семейству задач timetabling. У этого семейства нет одной универсальной сложности: результат зависит от точной формализации событий, временных слотов, ресурсов и ограничений. В этой записке формально определяется обобщённая задача допустимого расписания, доказывается её NP-полнота сведением от 3-раскраски графа и отдельно описывается, что этот результат означает для текущего прототипа.

**Ключевой вывод:** задача решения для обобщённой модели с явно заданными конфликтующими парами NP-полна. Это не является доказательством NP-полноты именно ограниченной модели, реализованной в Python-прототипе: для неё требуется отдельный анализ с учётом точной структуры данных и правил.

## 1. Термины и постановка

### 1.1. Решение и оптимизация — разные задачи

В задаче **решения** задан порог или набор жёстких ограничений; требуется ответить, существует ли допустимое расписание. Ответ «да» подтверждается конкретным расписанием-свидетельством.

В задаче **оптимизации** среди допустимых расписаний минимизируется стоимость, например сумма штрафов за окна и нежелательное распределение нагрузки. Если оптимизационная версия требует найти расписание с оценкой не выше заданного порога `B`, она задаёт соответствующую задачу решения. Утверждение NP-полноты относится к задаче решения, а NP-трудность оптимизации следует из NP-трудности соответствующей пороговой версии.

### 1.2. Обобщённая модель конфликтов

Пусть заданы:

- конечное множество занятий `V`;
- конечное множество временных слотов `T`;
- множество конфликтующих пар `E ⊆ {{u,v} : u,v ∈ V, u ≠ v}`. Два занятия из такой пары нельзя проводить одновременно;
- при необходимости — явно заданное множество разрешённых слотов `A(v) ⊆ T` для каждого занятия `v`.

**Задача допустимого расписания (GTT):** существует ли назначение `f: V → T`, такое что `f(v) ∈ A(v)` для каждого занятия (если списки `A` заданы) и `f(u) ≠ f(v)` для каждой конфликтующей пары `{u,v} ∈ E`?

В базовой версии без списков доступности каждый из `k = |T|` слотов может рассматриваться как цвет вершины графа конфликтов `G=(V,E)`. Следовательно, эта версия эквивалентна задаче `k`-раскраски графа.

## 2. Доказательство NP-полноты обобщённой модели

Используется классическая задача **3-раскраски графа**: дан конечный неориентированный граф `G=(V,E)`; можно ли раскрасить его вершины не более чем в три цвета так, чтобы концы каждого ребра имели разные цвета? 3-раскраска NP-полна.

### 2.1. Сведение

Для экземпляра 3-раскраски строим экземпляр GTT:

1. Для каждой вершины `v ∈ V` создаём занятие `x_v`.
2. Создаём три временных слота `T={t₁,t₂,t₃}`.
3. Для каждого ребра `{u,v} ∈ E` добавляем конфликтующую пару `{x_u,x_v}`.
4. Других ограничений не добавляем; все три слота доступны каждому занятию.

Преобразование выполняется за полиномиальное время: создаётся по одному занятию на вершину и по одному конфликту на ребро, то есть размер построенного экземпляра `O(|V|+|E|)`.

### 2.2. Корректность сведения

- **Если** `G` допускает правильную 3-раскраску `c: V → {1,2,3}`, назначим занятию `x_v` слот `t_{c(v)}`. Для каждого ребра `{u,v}` цвета различны, поэтому занятия не конфликтуют во времени. Получено допустимое расписание.
- **Если** построенный экземпляр GTT имеет допустимое расписание `f`, присвоим вершине `v` цвет `i`, когда `f(x_v)=t_i`. Для каждого ребра конфликт запрещает одинаковые слоты, следовательно, концы ребра получают разные цвета. Получена правильная 3-раскраска графа.

Таким образом, исходный граф 3-раскрашиваем тогда и только тогда, когда построенный экземпляр расписания допустим. Это полиномиальное many-one сведение доказывает NP-трудность GTT.

### 2.3. Принадлежность NP

Свидетельство для экземпляра — список назначенных слотов `f(v)` для всех занятий. Его размер полиномиален относительно входа. Проверяющий алгоритм проверяет, что каждый слот допустим, а у каждой конфликтующей пары слоты различаются. При явном списке конфликтов это занимает `O(|V|+|E|)` времени (плюс проверка представления списков доступности, если они присутствуют).

Следовательно, базовая GTT принадлежит NP и NP-трудна; значит, она **NP-полна**.

## 3. Что доказательство означает для школьного расписания

Результат показывает вычислительную трудность общей модели, в которой ограничения представлены произвольным графом конфликтов. Он объясняет, почему для общих случаев нельзя ожидать универсального точного и быстрого метода, если `P ≠ NP`.

Однако у прикладной модели школы структура конфликтов ограничена: занятие связано с конкретными учителем, классом, кабинетом, сменой и другими атрибутами. Преобразование выше разрешает задавать произвольный граф конфликтов, а текущая программа не принимает такой граф как вход. Поэтому сведение **не доказывает** NP-полноту любой более узкой модели со строго фиксированным набором школьных ресурсов.

Чтобы доказать NP-полноту конкретной школьной модели, необходимо:

1. зафиксировать, какие именно поля и ограничения входят в экземпляр;
2. определить, могут ли несколько занятий иметь произвольные пересекающиеся множества ресурсов или только по одному ресурсу каждого типа;
3. построить сведение, сохраняющее именно эти ограничения;
4. отдельно показать полиномиальную проверяемость допустимого расписания.

На практике школьные задачи timetabling широко изучаются как NP-трудные комбинаторные задачи; конкретные варианты и границы сложности зависят от модели. Обзор Schaerf (1999) и работа Even, Itai и Shamir (1976) описывают семейство таких постановок и методы анализа. Это не заменяет доказательство для отдельной реализации.

## 4. Сопоставление с кодом проекта

Текущая Python reference-реализация хранит занятие как час учебной группы и выбирает для него день и номер урока. Функция оценки проверяет совпадения учителя, класса и заданного кабинета в одном слоте, дневное ограничение количества уроков, физкультуру в соседние дни и несколько мягких штрафов.

Ограничения, которые важно учитывать при интерпретации результата:

- в текущей модели пока нет полноценной семантики смен;
- одновременные подгруппы одного класса корректно не моделируются;
- часть норм, пожелания учителей и доступность кабинетов по расписанию не реализованы;
- score генетического алгоритма — эвристическая оценка, а не сертификат оптимальности;
- нулевое число жёстких конфликтов означает допустимость только относительно проверок, которые реально написаны в `evaluate()`.

Таким образом, для прототипа строго обоснован следующий вывод: он эвристически ищет расписание в ограниченной модели проверяемых кодом условий. Обобщённое NP-полное доказательство является теоретическим обоснованием сложности семейства задач, но не сертификатом полноты требований или корректности школьного расписания, выдаваемого приложением.

## 5. Практические последствия и выбор методов

Если имеется `n` занятий и `m` слотов, полный перебор назначений может иметь до `m^n` вариантов. Проверки ограничений позволяют отсекать часть вариантов, но не устраняют в общем случае комбинаторный рост.

Для прототипа оправдана комбинация методов:

- **валидация исходных данных** до запуска — обнаруживает отсутствующие ссылки и заведомо некорректные поля;
- **генетический алгоритм** — эвристический глобальный поиск по пространству расписаний;
- **локальный поиск / ремонт конфликтов** — попытки исправить найденный вариант;
- **независимая повторная оценка** результата и отображение оставшихся нарушений;
- **тесты на небольших экземплярах с известным ответом** и регрессионные тесты.

Эти методы не дают общего доказательства, что алгоритм найдёт допустимое расписание, если оно существует, или докажет его отсутствие. Если требуется гарантия выполнимости/невыполнимости на определённом классе входов, следует рассмотреть точный CP-SAT/SAT/ILP-решатель и выдачу проверяемого свидетельства либо статуса `unknown` при исчерпании лимита.

## 6. Рекомендуемые экспериментальные метрики

Для оценки прогресса проекта вместо неформального «процента работающего алгоритма» стоит фиксировать на версионируемом наборе тестов:

1. долю входов, прошедших валидацию и корректное построение контекста;
2. долю запусков, завершившихся допустимым расписанием в пределах установленного времени;
3. число нарушений каждого жёсткого ограничения отдельно;
4. мягкий штраф и время поиска;
5. повторяемость результата при фиксированном seed;
6. корректность экспорта/импорта: после round-trip совпадают все назначения;
7. размеры экземпляров: число классов, групп, часов, учителей, кабинетов и слотов.

Для каждого результата нужно указывать точную версию модели и набор учитываемых ограничений. Иначе сравнение процентов качества вводит в заблуждение.

## Заключение

Задача допустимого расписания в обобщённой модели произвольных конфликтующих пар NP-полна: она принадлежит NP, а NP-трудность следует из полиномиального сведения от 3-раскраски. Для прикладного проекта это аргумент в пользу эвристик, строгой валидации, измеримых тестов и прозрачного сообщения оставшихся конфликтов. Это утверждение нельзя без дополнительного сведения переносить на текущую ограниченную реализацию; её качество определяется набором реально реализованных правил и экспериментальной проверкой.
