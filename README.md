# School Scheduler — рабочий прототип

Десктопный прототип на Python: генетический алгоритм + локальное устранение конфликтов (бэктрекинг), графический интерфейс на PySide6 и тестовый набор данных.

## Требования и запуск

- Python 3.11 или новее
- Установка зависимостей: `python -m pip install -r requirements.txt`
- Запуск из корня проекта: `python -m app.main`

На Linux требуется графическая сессия для Qt. Если в системе нет дисплея, можно проверить алгоритм и тесты без запуска GUI.

## Что работает в прототипе

- Окно запускается через основную точку входа `app.main`.
- Генетический алгоритм действительно выполняется на тестовых данных; фиктивный прогресс и заранее зашитые метрики удалены.
- Расчёт вынесен в фоновый поток, GUI остаётся отзывчивым; поиск можно остановить.
- Интерфейс показывает фактические жёсткие конфликты, мягкие штрафы и расписание выбранного класса.
- Единая светлая тема с цветовой маркировкой предметов.
- Двойной щелчок по расписанию позволяет переместить выбранный час в другой слот; перемещение в занятый слот выполняет обмен, если там ровно один урок. Приложение предупреждает, если правка увеличит число жёстких конфликтов.
- Расписание можно сохранить в JSON и открыть обратно через кнопки в окне. Файл содержит версию формата, группы и все размещённые часы; загрузка проверяет совместимость данных и корректность слотов.
- Скрипт `scripts/run_from_db.py` демонстрирует отдельный сквозной сценарий с SQLite: тестовая база → контекст → генерация → сохранение результата.
- Исследование сложности и NP-полноты опубликовано в [`docs/np_completeness_research.md`](docs/np_completeness_research.md).

## Проверки

```bash
python -m unittest discover -s tests -v
python scripts/run_sample.py
```

Для SQLite-сценария потребуется SQLAlchemy из `requirements.txt`:

```bash
python scripts/run_from_db.py /tmp/school-scheduler-demo.sqlite3
```

## Ограничения прототипа

Интерфейс использует демонстрационную школу, а не введённые пользователем данные. JSON-файлы этой версии привязаны к этому набору групп и не являются импортом произвольной школьной базы. В Python-модели ещё не реализовано полноценное учётывание деления на подгруппы, смен, всех правил СанПиН, пожеланий учителей и доступности кабинетов по сменам. Поэтому результат нужно рассматривать как демонстрацию алгоритмического контура, а не как готовое расписание для использования школой. Если жёсткие конфликты остались, интерфейс показывает это явно и не выдаёт результат за успешный.

Алгоритм эвристический: отсутствие найденных конфликтов означает допустимость только относительно тех ограничений, которые сейчас закодированы, но не гарантирует оптимальность.
