# School Scheduler

Десктоп-приложение для автоматизированного составления школьного расписания
(гибридный алгоритм: генетический алгоритм + бэктрекинг). См. `docs/TZ_shkolnoe_raspisanie_v2.md`.

## Статус: что уже реально работает

Алгоритмическое ядро (hard/soft ограничения раздела 4 ТЗ, ГА, бэктрекинг)
реализовано **дважды и оба варианта проверены запуском**:

1. **C++ (`core/`)** — компилируется и прогоняется автономным смоук-тестом
   БЕЗ pybind11/CMake (см. "Быстрая проверка C++ ядра" ниже). На тестовой
   школе (14 подгрупп, 46 уроков/неделю) доходит до 0 hard-конфликтов
   к ~17-му поколению.
2. **Python reference (`app/services/reference_scheduler.py`)** — работает
   без единой внешней зависимости (только стандартная библиотека), можно
   запускать прямо сейчас: `python3 scripts/run_sample.py`. Использует ту же
   модель данных и те же формулы штрафов, что и C++-ядро — удобно для
   отладки логики без сборки C++, и как эталон для сверки результатов ядра.

Обе реализации на одинаковых входных данных сходятся к расписанию без
жёстких конфликтов — это подтверждено, не предположение.

Что ещё НЕ реализовано (осталось как TODO вне текущей задачи):
- GUI (`app/ui/`) — только структура папки;
- собственно сборка pybind11-модуля (исходники в `core/src/bindings.cpp`
  готовы, но требуют pybind11 — см. ниже);
- импорт/экспорт Excel/PDF;
- перенос данных на новый учебный год, автосохранение прогресса генерации.

## Полный пайплайн: БД → алгоритм → БД (уже работает)

```bash
python3 scripts/run_from_db.py
```

Создаёт `school.sqlite3` по `db/schema.sql`, заполняет тестовой школой
(4 класса, 2 смены, деление на подгруппы по иностранному языку — раздел 3 ТЗ),
собирает `ScheduleContext` из БД (`app/services/db_context_builder.py`),
запускает генерацию, **пишет результат в таблицу `timetable_entries`**
и тут же читает его обратно, чтобы подтвердить, что персист реально работает.

Мост `db_context_builder.py` сознательно написан на встроенном `sqlite3`,
а не на SQLAlchemy — чтобы его можно было гонять без установки зависимостей.
`app/data/models.py` (SQLAlchemy) остаётся как основа для GUI-слоя, когда
до него дойдёт очередь; переписать мост под сессии SQLAlchemy — тривиально,
логика построения контекста не изменится.

## Быстрая проверка C++ ядра (без CMake/pybind11)

```bash
cd core/tests
g++ -std=c++20 -O2 -I../include smoke_test.cpp \
    ../src/fitness.cpp ../src/genetic_algorithm.cpp ../src/backtracking.cpp \
    -o smoke_test
./smoke_test
```

Ожидаемый результат: `hard_conflicts=0` и распечатка расписания класса 101.

## Быстрая проверка Python reference-реализации

```bash
python3 scripts/run_sample.py
```

Не требует `pip install` — использует только стандартную библиотеку.

## Сборка полноценного pybind11-модуля (когда понадобится GUI)

Требует интернет для установки зависимостей (в песочнице, где собирался
этот каркас, сети нет — поэтому модуль здесь не собирался и не тестировался,
только его исходный код в `core/src/bindings.cpp`):

```bash
pip install pybind11
sudo apt install cmake   # или через пакетный менеджер вашей ОС
mkdir build && cd build
cmake ../core -DCMAKE_BUILD_TYPE=Release
make
```

## Установка Python-зависимостей для остального приложения

```bash
pip install -r requirements.txt
```

(`reference_scheduler.py` и `scripts/run_sample.py` эти зависимости не используют.)

## Структура репозитория

```
core/           C++ вычислительное ядро (ГА + бэктрекинг)
  include/      заголовки (model.hpp, fitness.hpp, genetic_algorithm.hpp, backtracking.hpp)
  src/          реализация (fitness.cpp, genetic_algorithm.cpp, backtracking.cpp) + bindings.cpp
  tests/        smoke_test.cpp — автономный тест без pybind11

app/            Python-приложение
  ui/           экраны (PySide6) — пока не реализовано
  data/         models.py — рабочие SQLAlchemy-модели, зеркалящие db/schema.sql
  services/     reference_scheduler.py — рабочая Python-реализация алгоритма

db/             schema.sql — эталонная схема SQLite (проверена, применяется без ошибок)

docs/           ТЗ и сопутствующая документация

scripts/        run_sample.py — демо-запуск reference-планировщика на тестовой школе

tests/          интеграционные тесты Python-слоя — пока не реализовано
```

## Целевые платформы
Windows 10/11, Linux (сборка через CMake + Qt).
